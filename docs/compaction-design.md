# Concord Compaction Design — the durable-knowledge tier

> **Status:** Design — shapes CD-0002 §2c into a buildable pattern; canonical home,
> locator, publish proof, and bounded lazy pruning are binding under accepted PM6/PM7.
> **Depends on:** [`decisions/CD-0002-concord-state-authority.md`](./decisions/CD-0002-concord-state-authority.md) §2c (three storage tiers) and §2d (structured-artifact policy).
> **Companion to:** [`decisions/CD-0003-concord-storage-layer-shape.md`](./decisions/CD-0003-concord-storage-layer-shape.md).

## Purpose

CD-0002 §2c fixed the *shape* of the durable-knowledge tier (git markdown, one-way,
non-authoritative, one note per completed unit) and named the anti-pattern it corrects
(large predecessor serialization dumps). This design specifies **how
compaction actually works**: the function, the template, the generation pattern, the
salvage rule, the authority/index split, and when it runs.

The goal: durable knowledge that is **human-readable, versioned, greppable, and a few
kilobytes per unit** — written for a future reader, never a state dump.

---

## 1. The two-store authority pattern (symmetric with the live tier)

The durable tier mirrors the live tier's authority/projection split:

| | Live operational tier | Durable-knowledge tier |
|---|---|---|
| **Authority** | `domain_events` log (append-only) in SQLite | **git markdown notes** in the repo |
| **Derived projection** | explicit typed Product-memory tables (disposable, rebuildable — I3) | **`archived_work` plus historical-scope indexes** in SQLite (disposable, rebuildable from git) |

**Git is the authority for durable knowledge.** SQLite holds a lightweight **derived
index** of it for fast structured queries:

```sql
archived_work(id, type, title, completed_at, outcome_tag, lesson_tags,
  terminal_state, priority, summary, successor_work_id?, home_project_id,
  home_locator_id, note_path, commit_oid, content_hash)
archived_work_products(work_id, product_id)
archived_work_projects(work_id, project_id)
archived_work_components(work_id, component_id)
archived_work_tags(work_id, tag_id)
```

This is the PM7 logical projection shape, not final DDL. The scope-edge indexes
preserve frozen compaction scope without copying lifecycle or readiness state.

This index is **non-authoritative and rebuildable** — it is the I3 pattern applied to
the durable tier. If it is lost or drifts, it is regenerated by walking canonical
in-tree markdown note directories and validating PM6 front matter/content proofs.
`home_project_id`/`home_locator_id` come from the canonical home repository being
walked, not from mutable path/remote text inside the note.
It exists purely so "show me lessons tagged `auth`" or "what shipped last month?" is a
fast structured query, not a repo-wide grep.

**Why this is not the split-authority disease:** the index is one-way derived from the
notes (write a note → index it); no code path consults the index to *decide* anything
about a note. I1 holds.

## 2. The compaction function

On reaching terminal state, an entity's transition history is distilled into **one
markdown note**. The function is explicit about what crosses the boundary:

### In → the note
- **Outcome** — what shipped (one paragraph; the deliverable, not the process).
- **Why it mattered** — the value/motivation, for a reader who wasn't there.
- **Key decisions + reasoning** — the 1–3 load-bearing choices and *why* (links to
  decision records where they exist).
- **Transferable lesson(s)** — what a future effort should reuse or avoid. This is the
  highest-value field; it is what makes the tier worth maintaining.
- **Links** — commits, PRs, decision records, related entities, source files.

### Out → process exhaust (dropped)
- The full transition history (it's in SQLite; it's the *process*, not the knowledge).
- Sub-agent reports, briefing digests, contract-traceability dumps.
- Intermediate state snapshots, tool-call logs, retry/error machinery output.

The note is **distillation, not mirroring**: a reader learns the *outcome and the
lessons*, not the step-by-step. Target length: **one page (≤ ~4 KB)** — substantially
smaller than a per-unit process archive.

---

## 3. The salvage rule (the quality bar)

**Nothing valuable is lost; only process noise is.** Before exhaust is dropped, the
compaction must extract any **transferable finding** — a sub-agent insight, a measured
surprise, a rejected alternative with a reason — into the note's *Transferable
lesson(s)* field.

The falsifier: if you ever reach for a dropped sub-agent report later, the compaction
missed a lesson. Accepted PM9 keeps this as a **quality bar on the compaction function**,
not a separate store or receipt; the existing terminal event, approved note, and PM6
locator are the audit sequence.

---

## 4. The generation pattern — agent-drafts, operator-approves (HITL)

The note is **drafted by an agent from the terminal entity state**, then **approved by
the operator** before it is committed to git. This matches the existing spec-as-laws
HITL pattern and avoids both failure modes:

| Pattern | Failure mode | Verdict |
|---|---|---|
| Auto-generate from terminal state | Becomes a serialization dump | rejected |
| Pure human-authored | Inconsistent, lossy, doesn't happen under load | rejected |
| **Agent drafts → operator approves** | Bounded operator load; agent does the distillation work; human gates quality | **adopted** |

The operator's approval is the moment the note becomes durable knowledge. Until then it
is a draft (in SQLite, in-flight).

## 5. Directory, naming, template

### Directory
```
docs/decisions/CD-NNNN-slug.md        # durable decisions (already exist; cross-cutting)
docs/work/YYYY-MM-DD-slug-id.md       # completed-work notes (per unit)
docs/lessons/YYYY-MM-DD-slug.md       # standalone transferable lessons (cross-cutting, not tied to one unit)
```
`work/` is per-unit; `lessons/` is for findings general enough to stand alone; `decisions/`
is for architecture commitments. A unit's note links to any decisions/lessons it produced.

### Naming
`YYYY-MM-DD-kebab-slug-{work-id-suffix}.md` for work notes (date = terminal date).
The stable ID suffix prevents same-day slug collisions.

### Template (the work-note)
```markdown
---
concord_work_id: {stable work ID}
work_type: {kind}
title: {title}
completed_at: {timestamp}
outcome_tag: {bounded outcome category}
lesson_tags: [{bounded tags}]
terminal_state: {completed | cancelled | superseded}
priority: {priority}
summary: {bounded value/outcome summary}
product_ids: [product-...]
project_ids: [project-...]
component_ids: [component-...]
tag_ids: [tag-...]
successor_work_id: work-... # required only when superseded
---

# {title}

> Completed {YYYY-MM-DD} · {entity type} · [{commit/PR link}]

## Outcome
{one paragraph: what shipped}

## Why it mattered
{one paragraph: the value/motivation}

## Key decisions
- {decision} — {one-line reason}. [link to CD-NNNN if applicable]

## Transferable lessons
- {lesson} — {what to reuse or avoid, and why}

## Links
- commits / PRs / decisions / related entities / source files
```
The template is intentionally short. Required bounded front matter reconstructs the
derived index and PM7 historical-scope edges; optional body fields that would be empty
are omitted. Existing notes require PM7's bounded front-matter backfill before their
live projections become prune-eligible.

## 6. When compaction runs

**Default: after the terminal transition.** The agent drafts; the operator approves;
PM6 resolves/locks one home; git commit/content proof completes; then SQLite records
the compaction-link event and derived index. Only then are operational rows **eligible
for pruning**.

**Accepted PM7 retention rule:** durable linkage makes terminal rows prune-eligible;
it does not itself delete live projections or `domain_events`. A later bounded lazy
operation may prune only verified eligible projections, never based on calendar age.
Each item commits atomically, retains authoritative events, and leaves a rebuildable
git-derived historical index. A pruned work ID is immutable; renewed need creates a
new work ID linked through PM7's cross-tier `archived_work_linked` event and
`archived_work_links` projection.

**Batch backfill intent (tool shape deferred):** a bounded operation may walk
uncompacted terminal work and draft notes for legacy/missed compaction. TS decisions
own any command/tool surface.

## 7. The full storage-layer picture (after CD-0002 + PM2–PM7 + this design)

```
                    ┌─────────────────────────────────────────────┐
  LIVE (authority)  │ SQLite, one global local authority          │
                    │  domain_events (append-only authority)       │
                    │    └─► explicit typed Product-memory tables  │   (materialized folds; I3)
                     │  artifacts (TEXT; no WIP byte store)        │   (CD-0002 §2d, PM8)
                    └─────────────────────────────────────────────┘
                              │ terminal transition + operator approval
                              ▼
                 ┌──────────────────────────────────────────────┐
  DURABLE        │ git markdown, in the PM6-selected home       │
  (authority for │  docs/work/*  docs/lessons/*  docs/decisions/*│
   knowledge)    └──────────────────────────────────────────────┘
                              │ indexed (derived, non-authoritative)
                              ▼
                 ┌──────────────────────────────────────────────┐
   INDEX          │ SQLite: archived_work + frozen scope edges   │
                  │ (rebuildable from git; fast history queries) │
                 └──────────────────────────────────────────────┘
                              │
                   process exhaust (sub-agent reports, digests,
                   traceability) → producer-owned; PM9 no separate receipt
```

Two authorities, two scopes, never competing: SQLite owns *operational* state;
git owns *knowledge*. The SQLite index of git is derived and one-way. I1 holds across
both tiers.

---

## 8. Open details (not blocking the storage spine)

- **Storage-pressure threshold and batch limits** — PM7 intentionally sets no default;
  choose only from representative-size evidence and operate through bounded cursors.
- **Lesson extraction quality** — the salvage rule's effectiveness is itself measurable
  (frequency of "reaching for a dropped report"); instrument it.
- **Cross-note linking conventions** — settle as the corpus grows; start with markdown
  links + slugs.
- **Backfill tooling** — build when first needed (likely never, if compaction runs at
  terminal by default).

These are operational tunings, not architecture forks. The shape above is complete.
