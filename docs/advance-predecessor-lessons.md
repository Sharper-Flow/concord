# Advance predecessor lessons

**Status:** Public, non-authorizing design input.

These concise lessons are keyed only to reachable public Advance issue records. They
do not reproduce private inventories, local snapshots, archive bundles, or private
history. They identify mechanisms Concord must prevent structurally, not work that
Concord must implement or synchronize.

| Public source | Lesson for Concord |
|---|---|
| [Advance #348](https://github.com/Sharper-Flow/Advance/issues/348) | One subject must have one durable authority; a writable projection must not compete with the authoritative record. |
| [Advance #205](https://github.com/Sharper-Flow/Advance/issues/205) and [#192](https://github.com/Sharper-Flow/Advance/issues/192) | Cross-project work needs explicit context and serviceability evidence; path plumbing alone is not an authority model. |
| [Advance #325](https://github.com/Sharper-Flow/Advance/issues/325) | Evidence producers and consumers need attributable, durable bindings; a report cannot manufacture proof. |
| [Advance #349](https://github.com/Sharper-Flow/Advance/issues/349) and [#354](https://github.com/Sharper-Flow/Advance/issues/354) | A successful acknowledgement must correspond to durable persistence; partial outcomes must remain visibly partial. |

These lessons are referenced by the public constitutional docs as predecessor
evidence. They do not create a second development authority or a Concord runtime
dependency.
